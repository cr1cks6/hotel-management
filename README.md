# Hotel Management System

## Тема проекта
Реализация серверной части (REST API) системы управления отелем. 
Проект позволяет автоматизировать основные бизнес-процессы гостиничного бизнеса: управление номерным фондом, регистрацию гостей, оформление бронирований с проверкой занятости и проведение финансовых расчетов.

В рамках Лабораторной работы №3 проект переведен на использование реляционной базы данных (PostgreSQL), реализованы связи между таблицами и сложные транзакционные операции.

## Основные сущности
База данных состоит из 5 связанных таблиц:

1. **Hotel** (Отель) — Информация о гостинице (Название, Адрес). Является родительской сущностью для комнат.
2. **Room** (Комната) — Номерной фонд. Содержит номер комнаты, цену за ночь и ссылку на Отель.
3. **Guest** (Гость) — Персональные данные клиентов (ФИО, Email, Телефон).
4. **Booking** (Бронирование) — Центральная сущность, связывающая Гостя и Комнату на определенный диапазон дат (Check-in / Check-out). Хранит статус активности.
5. **Payment** (Платеж) — Финансовая запись, привязанная к конкретному бронированию. Хранит сумму оплаты.

## Реализованные бизнес-операции
Сервис реализует 5 сложных операций, затрагивающих несколько таблиц одновременно:

### 1. Бронирование с автоматическим депозитом
*Логика:* Клиент выбирает номер. Система проверяет доступность, рассчитывает полную стоимость проживания (Цена номера * Дни) и **автоматически создает запись о платеже (депозит 50%)**.
*   **Метод:** `POST /api/bookings`
*   **Затрагиваемые сущности:** `Booking` (создание), `Room` (чтение цены), `Payment` (автоматическая вставка), `Guest`.

### 2. Умный поиск свободных номеров
*Логика:* Выборка номеров конкретного отеля, которые гарантированно свободны в указанный период дат. Используется сложный SQL-запрос для исключения пересечений с активными бронями.
*   **Метод:** `GET /api/rooms/available`
*   **Затрагиваемые сущности:** `Room`, `Booking`.

### 3. Выселение и финальный расчет (Check-out & Pay)
*Логика:* При выезде гостя система суммирует все уже внесенные платежи (депозит), вычисляет остаток долга и **автоматически создает финальный платеж** на недостающую сумму, после чего закрывает бронь (снимает статус активности).
*   **Метод:** `POST /api/bookings/{id}/checkout`
*   **Затрагиваемые сущности:** `Booking` (обновление статуса), `Payment` (чтение истории и вставка нового), `Room` (для расчета полной цены).

### 4. Переселение гостя (Relocation)
*Логика:* Изменение номера в рамках существующего бронирования. Включает предварительную проверку доступности нового номера на те же даты. Если номер занят — операция отклоняется.
*   **Метод:** `POST /api/bookings/{id}/relocate`
*   **Затрагиваемые сущности:** `Booking` (обновление связи), `Room` (проверка доступности нового номера).

### 5. Финансовый отчет отеля
*Логика:* Агрегация данных по всему отелю. Сервис подсчитывает общую выручку (сумму всех платежей по всем броням этого отеля) и количество транзакций.
*   **Метод:** `GET /api/hotels/{id}/report`
*   **Затрагиваемые сущности:** `Hotel` -> `Room` -> `Booking` -> `Payment` (цепочка связей).

---
*Проект выполнен на стеке: Java 21, Spring Boot 3, PostgreSQL, Hibernate.*
