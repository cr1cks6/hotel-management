Hotel Management System (Lab 6: HTTPS & CI/CD)
📌 Описание проекта
Серверная часть (REST API) системы управления отелем.
В 6-й лабораторной работе фокус смещен на безопасность передачи данных и автоматизацию разработки. Проект переведен на защищенный протокол HTTPS с использованием собственной цепочки сертификатов, а также настроен процесс непрерывной интеграции (CI) для автоматической сборки и тестирования кода.
🛠 Технологический стек
Язык: Java 21
Фреймворк: Spring Boot 3.5.7
База данных: PostgreSQL
Безопасность: Spring Security 6, JWT, TLS/SSL (HTTPS)
DevOps: GitHub Actions (CI/CD)
Криптография: X.509 Certificates, Java Keystore (JKS)
🔐 Новые возможности (Lab 6)
1. Переход на HTTPS (TLS)
Сервер больше не принимает незащищенные HTTP-запросы. Весь трафик шифруется.
Порт: Сервер переехал с 8080 на 8443.
Цепочка сертификатов: Реализована PKI (Public Key Infrastructure) из трех звеньев:
Root CA (Корневой сертификат).
Intermediate CA (Промежуточный сертификат, подписанный корневым).
Server Certificate (Сертификат сервера, содержащий номер студенческого билета, подписанный промежуточным).
2. CI/CD Pipeline (GitHub Actions)
Настроен автоматический конвейер (Pipeline) в файле .github/workflows/maven.yml.
При каждом пуше в ветки main или lab_6 выполняются следующие шаги:
Checkout & Setup: Подготовка окружения (Ubuntu + Java 21).
Database Service: Поднятие временного контейнера PostgreSQL для прогона тестов (интеграционное тестирование).
Secrets Management: Безопасное извлечение keystore.jks и паролей из GitHub Secrets.
Tests: Запуск тестов (mvn test), которые подключаются к временной БД.
Build: Сборка jar файла.
Artifacts: Загрузка собранного приложения в артефакты GitHub.
🔐 Архитектура безопасности (JWT из Lab 5)
Сохранена логика из предыдущей работы:
Stateless: Access (15 мин) + Refresh (30 дней) токены.
Session Management: Контроль активных сессий через БД.
Reuse Detection: Защита от кражи Refresh-токенов.
🗂 Структура Базы Данных
Система использует 7 таблиц:
Hotel, Room, Guest — Основные сущности.
Booking — Бронирования.
Payment — Финансовые операции.
App_Users — Пользователи и роли.
User_Sessions — Хранение Refresh-токенов.
💼 Бизнес-операции
Бронирование (POST /api/bookings) — Транзакционное создание брони и платежа.
Поиск (GET /api/rooms/available) — Умный поиск свободных дат.
Выселение (POST /checkout) — Финализация счета.
Переселение (POST /relocate) — Смена номера.
Отчет (GET /report) — Финансовая статистика.
🚀 Инструкция по запуску и проверке
1. Настройка переменных
Для локального запуска убедитесь, что в переменных среды или в конфигурации IDE заданы:
DB_USERNAME / DB_PASSWORD — для PostgreSQL.
Либо настроен application.properties на использование локального .jks файла.
2. Запуск приложения
При успешном старте в логах появится:
Tomcat started on port 8443 (https)
3. Проверка через Postman / Браузер
⚠️ Важно: Теперь все запросы должны идти на протокол HTTPS.
Адрес: https://localhost:8443/...
Сертификат: Поскольку сертификат самоподписанный (наш собственный CA), браузер/Postman выдаст предупреждение.
В браузере: Нажать "Дополнительно" -> "Перейти на сайт (небезопасно)".
В Postman: Settings -> General -> выключить "SSL certificate verification".
4. Проверка CI/CD
Зайдите во вкладку Actions в репозитории GitHub.
Убедитесь, что последний Workflow имеет статус Success (Зеленая галочка ✅).
В деталях сборки можно увидеть шаги Run Tests и Build JAR.
Собранный .jar файл можно скачать в разделе Artifacts.
